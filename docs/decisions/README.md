# Decision Log

PAWS membership rotates every year. Undocumented decisions get re-argued, and the team loses the context behind old tradeoffs. This log keeps the reasoning visible for future firmware, mechanical, and ML/AI members.

Write a decision record when the team makes a choice that will be expensive or confusing to revisit later, such as:

- firmware architecture, board responsibilities, protocol boundaries, or toolchain versions
- mechanical geometry, actuator choices, vendor part changes, or manufacturing constraints
- simulation fidelity, observation/action spaces, training pipelines, or deployment formats
- repository conventions that affect more than one person
- a rejected option that future members are likely to suggest again

Do not write a record for routine implementation details, one-off bugs, or choices that are obvious from a small code diff.

Decision records are append-only. Do not edit old records to change history. If the team reverses a decision, create a new record that supersedes the old one and explains why the context changed.

Use `TEMPLATE.md` for new records.
